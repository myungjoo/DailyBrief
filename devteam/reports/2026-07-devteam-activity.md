**데이터 한계** (이 리포트를 읽기 전에 반드시 확인)

1. **사내 GitHub Enterprise는 조회 대상이 아니다.** 로스터 `host`가 `github.com`이므로 보이는 것은
   부서원 각자의 **공개 오픈소스 활동뿐**이다. 사내 전용 코드 작업은 이 리포트에 한 줄도 반영되지 않는다.
2. **조회 계정 비대칭**: 조회에 쓰인 토큰이 로스터 대상 중 한 명(`myungjoo`)의 계정이다.

   ① 실제 0건, 또는 ② 프로필에서 비공개 기여 표시를 끈 경우(이 경우 타인 토큰에는 0으로 나온다)

## 기술 방향 관찰

- **관심 영역(On-Device LLM · Runtime · Compiler · 경량화)과 직결되는 코드 활동은 이번 회차 공개 범위에서
  거의 관측되지 않았다.** 팀 커밋 1,369건의 언어 축은 TypeScript 794건(58%, 평가 에이전트 1개 레포)과

  단정할 수 있는 것은 "관측되지 않았다"까지이며, 사내 Enterprise 미포함이 그 주된 이유일 수 있다.
- **연구 축에서는 정렬이 보인다.** `leemgs`의 논문 레포군이 커널 오토튜닝(`semantos`) ·
  계층 메모리 오케스트레이션(`orion`) · 힙 메모리 안전(`heap-memory-safeguard`) ·
  커널 스케줄링(`sched_brs`)으로, 관심 영역의 Runtime·경량화 축과 주제가 맞닿는다.
  다만 산출 형태가 **구현 코드가 아니라 논문·재현 패키지(TeX)**라는 점은 구분해 둘 필요가 있다.
- **로컬 LLM 접점은 `myungjoo` 쪽에 하나 있다.** `llama-server` 런너 정리와 Ollama LAN 셋업으로
  로컬 추론을 실 파이프라인에 붙이는 작업이 진행 중이다(다만 해당 이슈는 9일 무진전).
  반대로 `leemgs`의 에이전트는 Gemini API 기반, 즉 클라우드 축이다.

- 주말 활동은 성실성의 근거가 아니다. **과부하 신호로만 쓴다.** 연속 활동일수도 미덕으로 쓰지 않는다.
