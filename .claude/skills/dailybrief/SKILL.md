# DailyBrief 메인 페이지 - 허브 갱신

`dailybrief-hub` 서브 에이전트를 호출해 통합 대시보드를 갱신한다.

## 실행

Agent 도구로 `subagent_type: "dailybrief-hub"` 를 호출한다. `run_in_background: false`.

프롬프트에 넘길 내용:

```
DailyBrief 메인 페이지를 갱신해라.
- 에이전트 정의의 STEP 0~6을 순서대로 모두 수행할 것.
- hub/config/agents.md 레지스트리를 먼저 읽고 통합 대상과 summary_fields 를 확정할 것.
- 개별 브리핑을 새로 생성하지 말 것. 기존 리포트·상태 파일을 읽어 모으기만 할 것.
- 다른 에이전트의 상태 파일을 수정하지 말 것(읽기 전용).
- 없는 데이터를 0으로 채우지 말고 미실행/상태 불명으로 구분할 것.
- 기본 탭은 '전체'이며 각 에이전트의 갱신 시점·신선도 배지·보유 데이터 요약을 카드로 보일 것.
- 호출 커맨드 칩은 클립보드 복사까지만 하고, 페이지에서 에이전트가 실행되는 것처럼
  보이게 만들지 말 것. 한계를 각주로 명시할 것.
- hub/state/artifact.json 의 url 이 있으면 그 url 로 갱신할 것(새 URL 생성 금지).
{추가 지시사항}
```

## 인자 처리

| 인자 예시 | 해석 |
|---|---|
| 인자 없음 | 표준: 전체 에이전트 통합 갱신 |
| `--refresh-all` / `전부갱신` | **먼저 각 에이전트를 순차 실행**해 산출물을 갱신한 뒤 허브를 갱신. 시간이 오래 걸린다 |
| `--refresh ondevice,invest` | 지정한 에이전트만 먼저 실행한 뒤 허브 갱신 |
| `--stale-only` / `정체만` | 신선도가 `정체`·`미실행`인 에이전트만 먼저 실행한 뒤 허브 갱신 |
| `--check` / `점검만` | 페이지를 발행하지 않고 신선도 판정 결과만 터미널에 보고 |
| `--tab invest` | 발행 후 해당 탭 해시(`#tab-invest`)가 붙은 URL을 반환 |
| `--register` | `.claude/agents/` 를 스캔해 레지스트리 미등록 에이전트만 보고 |

`--refresh*` 계열은 허브가 직접 수집하는 것이 아니라 **해당 에이전트를 먼저 호출**하는 것이다.
호출 순서는 `ondevice-llm-monitor` → `ai-capital-monitor` → `dev-activity-monitor`.
각 호출은 독립이므로 실패해도 다음으로 넘어가고, 실패한 에이전트는 허브에서 `상태 불명`으로 표시된다.

## 완료 후

에이전트가 반환한 요약(메인 페이지 URL · 에이전트별 한 줄 · 조치 필요 항목 · 미등록 에이전트)을
그대로 전달한다.

**메인 페이지 URL을 전달할 때 반드시 함께 알린다**: `개발 활동` 탭에 부서원 실명과 개인별
산출 지표가 들어 있으므로, 공유하면 그 내용이 함께 노출된다. 사용자가 공유를 지시하지
않았다면 공유 방법을 먼저 제안하지 않는다.
