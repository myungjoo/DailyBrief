# 개발 활동 브리핑 - 수동 실행

`dev-activity-monitor` 서브 에이전트를 즉시 호출해 부서원 활동 브리핑을 생성한다.

## 사전 점검 (에이전트 호출 전에 직접 확인)

1. `devteam/config/roster.md` §1에 **실제 GitHub ID가 들어 있는지** 확인한다.
   예시 행(`github-id-1` 등)만 남아 있으면 에이전트를 호출하지 말고 사용자에게 먼저 알린다:
   > 로스터에 실제 부서원 GitHub ID를 기입해 주십시오: `devteam/config/roster.md` §1
   > 형식은 `| github-id | 이름 | 팀 | 역할 | 담당 영역 | 비고 |` 입니다.
2. `gh auth status` 를 확인한다. 미로그인이면 사용자에게 안내한다(직접 로그인하지 말 것):
   > 세션에 `! gh auth login` 을 입력해 주십시오.
   > 사내 GitHub Enterprise 대상이면 `! gh auth login --hostname <사내호스트>` 입니다.

## 실행

Agent 도구로 `subagent_type: "dev-activity-monitor"` 를 호출한다.
`run_in_background: false` 로 실행해 결과를 바로 받는다.

프롬프트에 넘길 내용:

```
부서원 GitHub 활동 브리핑을 생성해라.
- 에이전트 정의의 STEP 0~8을 순서대로 모두 수행할 것.
- devteam/config/roster.md 를 먼저 읽고 대상 명단·조회 호스트·판정 기준을 확정할 것.
  로스터에 유효한 ID가 없으면 중단하고 보고할 것. ID를 추측하지 말 것.
- devteam/config/metrics.md 의 지표 정의와 금지 목록을 그대로 적용할 것.
- STEP 3(무엇을 하고 있는가)이 이 리포트의 본론이다. 숫자보다 작업 주제를 우선할 것.
- devteam/state/activity-history.json 에 스냅샷을 기록해 전월 대비 추이를 만들 것.
- 리포트에 '지표 해석 주의' 섹션과 비공개 기여 조회 불가 건수를 반드시 포함할 것.
- 인원을 단일 점수로 순위 매기지 말 것.
- 리포트 파일과 Artifact 대시보드를 모두 갱신할 것.
{추가 지시사항}
```

## 인자 처리

| 인자 예시 | 해석 |
|---|---|
| 인자 없음 | 표준: 최근 30일, 로스터 전원 |
| `--month 2026-07` / `7월` | 해당 월 1일~말일로 기간 고정 |
| `--since 3m` / `3개월` | 조회 기간 확장. 분기 리뷰용 |
| `--member github-id` / `홍길동` | 특정 인원만 심층 조회. PR 원문까지 확인해 작업 내용을 확장 |
| `--team Runtime` / `런타임팀` | 특정 팀만 |
| `--repo org/name` | 특정 레포 내 활동만 집계 |
| `--stalled` / `정체만` | 정체 항목만 추려 짧게. 주간 병목 점검용 |
| `--themes` / `무슨일` | 지표는 최소화하고 "누가 무엇을 하고 있는가"만. 기술 방향 점검용 |
| `--refresh` | `state/raw/` 캐시를 무시하고 API 재수집 |
| `--no-artifact` | 대시보드 발행 생략, 마크다운 리포트만 |
| `--compare 2026-06` | 지정한 과거 스냅샷과 비교 (기본은 직전 스냅샷) |

## 완료 후

에이전트가 반환한 요약(한 줄 요약 · 인원별 한 줄 · 주목 신호 · 파일 경로 · Artifact URL ·
데이터 한계)을 그대로 전달한다. 리포트 전문을 터미널에 다시 출력하지 않는다.

**Artifact URL을 전달할 때 반드시 함께 알린다**: 이 페이지에는 실명과 개인별 산출 지표가
들어 있으므로, 공유하면 그 내용이 그대로 노출된다. 사용자가 공유를 지시하지 않았다면
공유 방법을 먼저 제안하지 않는다.

**지표를 요약에 옮길 때 해석 경계를 유지한다.** 커밋 수가 적은 인원을 "저조"로 단정하지 않는다 -
비공개 기여·리뷰 중심 역할·휴가 가능성을 함께 전달한다.
