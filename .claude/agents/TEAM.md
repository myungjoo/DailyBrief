# 에이전트 팀 로스터

> 이 파일은 팀의 단일 진실 원천이다. 에이전트를 추가·삭제·개명할 때 같은 커밋에서 갱신한다.

## 현재 팀

| # | 에이전트 | 역할 | 수동 호출 | 작업 공간 | 실행 주기 | 모델 |
|---|---|---|---|---|---|---|
| 1 | `ondevice-llm-monitor` | On-Device LLM · Runtime · Compiler · 경량화 **기술 동향** 모니터링 및 임원 브리핑 생성 | `/ondevice-brief` | `monitor/` | 매일 아침 + 수동 | opus |
| 2 | `ai-capital-monitor` | LLM · NPU · NPU/LLM용 System Software 분야 **투자·펀딩·M&A** 추적. 스타트업 대규모 라운드($50M+)와 전략적 투자자 참여 딜 집중 | `/invest-brief` | `capital/` | 매주 월요일 + 수동 | opus |
| 3 | `dev-activity-monitor` | 부서원 **GitHub 활동** 수집 - "무엇을 하고 있는가" + 산출 지표 + 전월 대비 추이 | `/dev-activity` | `devteam/` | 수동 (월간 자동 등록 가능) | opus |
| 4 | `dailybrief-hub` | 위 세 에이전트를 **탭형 메인 페이지**로 통합. 기본 탭에 갱신 시점·신선도·보유 데이터 요약 | `/dailybrief` | `hub/` | 수동 (다른 에이전트 실행 후) | opus |

### 역할 경계 (혼동 방지)

- 1번은 **기술이 어디까지 왔나**(논문·릴리즈·벤치마크), 2번은 **자본이 어디로 가나**(라운드·밸류·투자자)를 본다.
  같은 회사가 양쪽에 등장할 수 있으나 관점이 다르다. 서로의 상태 파일을 건드리지 않는다.
- 3번은 **내부** 활동(우리 부서원), 1·2번은 **외부** 동향이다.

### 각 에이전트의 상태 파일 (초기화 금지)

| 에이전트 | 상태 파일 | 잃으면 복구 불가한 것 |
|---|---|---|
| `ondevice-llm-monitor` | `monitor/state/seen-index.json` | 5일 중복 제거 이력 |
| `ai-capital-monitor` | `capital/state/deal-ledger.json` | 회사별 누적 조달·밸류 이력 |
| `dev-activity-monitor` | `devteam/state/activity-history.json` | 월별 스냅샷 (GitHub API는 과거 집계를 되돌려주지 않는다) |

## 채용 예정 (빈 자리)

붙여넣은 프롬프트가 아래 성격이면 해당 슬롯에 배치한다. 슬롯은 고정이 아니라 참고용 분류다.

- **모니터링형** - 외부 정보를 주기적으로 수집해 변화를 보고. 상태 파일과 중복 제거가 필수.
  (예시: 경쟁사 제품 출시 추적, 특허 동향, 채용 공고로 본 조직 움직임)
- **분석/판정형** - 주어진 대상 하나를 깊게 파서 결론을 낸다. 상태 파일 불필요.
  (예시: 논문 기술 실사, 벤더 기술 주장 검증, 내부 제안서 리뷰)
- **작성형** - 임원이 대외/대내로 내보낼 문서를 초안한다. 톤과 포맷 규격이 핵심.
  (예시: 경영회의 보고자료, 기술 전략 메모, 대외 발표 스크립트)
- **운영형** - 반복 사무 처리를 자동화. 외부 시스템 연동이 있을 수 있다.
  (예시: 회의록 정리와 액션아이템 추적, 주간 실적 집계)

## 명명 규칙

- 에이전트 파일명 = `name:` 값 = 케밥케이스. 역할이 이름에서 드러나야 한다 (`<대상>-<동작>`).
- 수동 호출 스킬명은 사용자가 실제로 입력할 짧은 형태로 (`ondevice-llm-monitor` → `/ondevice-brief`).
- 작업 공간 디렉터리는 도메인 단수 명사 (`monitor/`, `review/`, `report/`).
